# engineering/storage.md

Purpose: Append-only JSONL is the durable job-history format: each event is ordered by a monotonically increasing per-job integer, and completed records remain available across process restarts.

## Themes
- Job-history persistence
- Per-job event ordering
- Restart-safe record readability

## Citations
- `engineering/storage.md:1-3` — Defines stored-record format, event numbering, and restart-readability requirement.

## Gotchas
- Do not rewrite, truncate, or reorder existing job-history events; storage is append-only.
- Event numbering is scoped to each job and must increase monotonically.
- A completed job's records must remain readable after the process exits and restarts.

## Recipes
- To record job history, append one JSONL event at a time and assign the next increasing integer within that job.
- To recover after restart, read the persisted finished records and resume from the job's existing event history.
