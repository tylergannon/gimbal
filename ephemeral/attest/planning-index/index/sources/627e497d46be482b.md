# engineering/retry-policy.md

Purpose: Retry delay is a pure, zero-based attempt-to-seconds calculation: clamp attempts to 0–4, multiply by 7, and perform no sleeping, scheduling, or I/O.

## Themes
- Implement bounded retry backoff
- Handle zero-based and negative attempts
- Keep delay computation pure and side-effect free

## Citations
- `engineering/retry-policy.md:3-3` — Defines the clamp, 7-second step schedule, and no-side-effects contract.

## Gotchas
- Attempt 0 and all negative attempts return 0 seconds.
- Attempts 4 and higher are capped at 28 seconds.
- The helper returns a number only; callers own sleeping and job scheduling.
- Do not interpret attempt as one-based.

## Recipes
- Compute delay as 7 * min(max(attempt, 0), 4).
- Expected values: attempt 0→0, 1→7, 2→14, 3→21, 4+→28.
- Unit-test boundary cases such as -1, 0, 1, 3, 4, and a large attempt.
- Use the returned seconds in an external retry mechanism; keep this helper free of I/O and timing operations.
