# billing/refunds.md

Purpose: Refund handling distinguishes approved credits, partial refunds, and unapproved requests. Approved credits must be issued within 11 calendar days; partial refunds preserve the original invoice identifier; unapproved requests carry no promised deadline.

## Themes
- Approved-credit SLA: issue within 11 calendar days (billing/refunds.md:3-3)
- Partial-refund identity preservation: retain the original invoice identifier (billing/refunds.md:3-3)
- Unapproved-request handling: no deadline commitment exists (billing/refunds.md:3-3)

## Citations
- `billing/refunds.md:3-3` — Defines the approval deadline, invoice-identifier rule, and absence of an unapproved-request deadline.

## Gotchas
- Do not apply the 11-day deadline to unapproved requests; the source promises no deadline for them (billing/refunds.md:3-3).
- Do not generate a new invoice identifier for a partial refund; preserve the original identifier (billing/refunds.md:3-3).

## Recipes
- To process an approved credit, track issuance against an 11-calendar-day deadline (billing/refunds.md:3-3).
- To process a partial refund, retain the original invoice identifier; for an unapproved request, communicate that no deadline is promised (billing/refunds.md:3-3).
