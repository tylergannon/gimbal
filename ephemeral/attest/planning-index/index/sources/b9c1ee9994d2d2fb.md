# operations/release.md

Purpose: Release operations leaf: normal deployments use a fixed UTC window; emergency patches require incident and on-call context; rollback must retain stored job history.

## Themes
- Scheduled deployment coordination: target 06:20–06:40 UTC for normal releases.
- Emergency change authorization: require both an incident reference and the current on-call engineer.
- Rollback data integrity: preserve stored job history during recovery.

## Citations
- `operations/release.md:1-3` — Complete release-window, emergency-patch, and rollback requirements.

## Gotchas
- The deployment window is UTC, so do not interpret it as local time.
- An emergency patch is incomplete without both required identifiers.
- A rollback that loses stored job history violates the operational rule.

## Recipes
- To schedule a normal deployment, select a time from 06:20 through 06:40 UTC.
- To prepare an emergency patch, record the incident reference and current on-call engineer first.
- To roll back safely, verify stored job history remains available before and after recovery.
