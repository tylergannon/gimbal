# security/secrets.md

Purpose: Secret-handling policy: job logs may expose credential metadata but never credential values; configuration exports must omit secret values.

## Themes
- Secret redaction in operational/job logging
- Credential metadata: record identifier and provider
- Secret-safe configuration export
- Auditability without secret disclosure

## Citations
- `security/secrets.md:3-3` — Defines the complete logging and configuration-export secret-handling rule.

## Gotchas
- Never write credentials themselves into job logs.
- Logging only the credential identifier and provider is permitted.
- A configuration export is intentionally incomplete because secret values are omitted.

## Recipes
- When instrumenting a job, log the credential identifier and provider fields only; redact or exclude the credential value.
- When exporting configuration, omit all secret values while retaining non-secret settings and credential metadata.
