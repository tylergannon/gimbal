# operations/backups.md

Purpose: Backup operations policy: create snapshots every six hours, retain the latest 24, and run restore drills on the first Tuesday of each month.

## Themes
- Backup scheduling: six-hour snapshot cadence.
- Retention management: preserve the 24 most recent snapshots.
- Recovery validation: perform monthly restore drills on the first Tuesday.

## Citations
- `operations/backups.md:1-3` — Defines the complete backup cadence, retention limit, and restore-drill schedule.

## Gotchas
- The policy specifies frequency and count, but not backup time zones, execution ownership, storage location, or failure handling.
- Retention is relative to recency: preserve the latest 24 snapshots rather than snapshots for a fixed calendar duration.
- A six-hour cadence yields approximately six days of coverage only if backups run consistently; this is an inference, not an explicit retention guarantee.

## Recipes
- To schedule backups, trigger snapshot creation every six hours and enforce retention by deleting snapshots older than the 24 most recent.
- To validate recoverability, schedule a restore drill for the first Tuesday of each month and document its outcome.
