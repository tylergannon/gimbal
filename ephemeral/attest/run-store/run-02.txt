[attempt.2 turn 1] **Token caching** (often implemented via KV caching or prompt caching) stores intermediate model computations so repetitive text doesn't need to be reprocessed from scratch.

When an LLM processes text, it calculates key-value (KV) representations for every token to evaluate attention. In multi-turn conversations, repeated system prompts, or large document queries, the beginning prefix of the prompt often stays identical across calls. 

Instead of recomputing attention states for these identical prefixes on every request, the system saves the KV activations in memory. When a new query arrives with a matching prefix, the model retrieves the cached states and processes only the newly added tokens.

This yields two significant benefits:
1. **Lower Latency:** Time-to-first-token (TTFT) drops dramatically because the prefill phase skips already-digested context.
2. **Reduced Cost:** Providers can charge significantly less for cached prompt tokens, making long-context workflows and persistent system instructions much more economical.

[attempt.1 turn 1] Token caching stores previously processed text representations so repeated requests can reuse them instead of recomputing the same work. In language-model systems, a prompt’s stable prefix may be cached, reducing latency and sometimes lowering input-processing costs. For example, instructions or conversation history that remain unchanged can be reused while only new text is processed. Caches typically have expiration limits, size limits, and rules about which content qualifies. They may be exact-match and sensitive to even small changes. Caching improves efficiency, but developers should consider privacy, invalidation, stale data, and whether cached content could expose information across users or sessions.
