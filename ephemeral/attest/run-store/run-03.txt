[attempt.2 turn 1] **Token caching** (or prompt caching) is an optimization technique that stores the intermediate representations—specifically the Key-Value (KV) attention states—of previously processed input tokens so they can be reused across multiple requests.

In large language models, computing attention over a long prompt is computationally expensive. When consecutive requests share identical static prefixes—such as system prompts, extensive documentation, codebases, or ongoing chat history—the inference engine skips reprocessing those tokens. Instead, it retrieves their precomputed activations directly from memory.

This provides three primary advantages:
1. **Reduced Latency:** Time-to-first-token (TTFT) drops dramatically because the model starts generating output immediately after the cached prefix.
2. **Lower Cost:** Most API providers offer significant discounts (often 50–90%) for cached input tokens compared to newly processed ones.
3. **Higher Throughput:** Serving hardware saves compute cycles, allowing higher concurrency and sustained context efficiency.
