# User decisions made after the issue comment

These are requirements from the conversation with Tyler, recorded for the independent review. Later conversation decisions supersede conflicting issue/comment text. The implementation-plan.md and graph-model.md are the design being reviewed, not independent evidence of satisfying these requirements.

- The requested deliverable is an implementation handoff for Sol, including the actual struct definition for workflow.Graph, based on issue 201 and its notes/comments. This task has been collaborative design work, not production implementation.
- Workflow structure should be explicit and statically mappable. Lint against hidden dynamic dispatch as with dynamic Set/SetJSON keys. Primitive variability such as loop counts, []Task contents, branch choices, prompts, and arguments is expected. Prefer explicit authoring over elaborate analysis.
- Explicitly select workflows and Go Input types at build time. Generate concrete bindings, schemas, types, and codecs via polytype/skgo. Each web-startable workflow has an authored Svelte page and application link. Runtime registration and generic schema-driven launch forms are superseded. Tyler proposed gimble generate-bindings with -workflow-type, optional -out, and optional -pkg.
- Operation is a sealed interface union. The accepted conceptual model is nested ordered bodies with AgentCall, Command, Set, SetJSON, Subgraph, and relevant Exit; subgraphs describe Sequence, Condition, Loop, Scope, and Group. Sessions have identity and ownership separate from their calls. Set/SetJSON retain source positions and expressions. Conditions do not themselves create Gimble scopes.
- Supervision is an unordered hierarchy attached beside the watched call. Higher supervisors watch their immediate supervisor's look turns. Supervisor sessions may be owned in an ancestor scope and reused across sequential tasks while their attachments/execution/visual placement remain local to watched child calls. Local session creation instead gives fresh conversations per task. Repeated appearances do not duplicate session identity, turns, or usage. Shared sessions still permit one active turn at a time.
- Tyler explicitly corrected further control-flow modeling: "avoid the temptation to model the program" and "putting a scoped group of agent calls in the right order is fine." The proposed reconstruction of launches, joins, caller work, and arbitrary exec.Cmd lifecycles was withdrawn. Command result detail is secondary.
- Tyler requested one approved/opinionated command execution function so its calls can be captured directly, with direct exec package use in workflow authoring linted against. The API name and signature have not yet been selected.
- Tyler resolved graph revision identity by asking "Why not just record the shape as JSON when the run begins?" and then requesting it be written down. Save the supplied generated Graph with the run; the viewer reads that snapshot. This replaces source fingerprint/revision matching and historical lookup against compiled graphs. The canonical Go model is serialized through polytype.

The latest instruction is to build gimble and use gimble run-prompt with Claude Fable 5.1 to review the handoff against the issue definition.
