# Claude Haiku structured output stalls in live workflow turns

https://github.com/tylergannon/gimbal/issues/351
State: OPEN

## Reproduction

On 2026-09-21, from the current Gimble tree, start the supported visible interview workflow in a disposable work directory:

```sh
go run ./cmd/examples/interview --work-dir "$(mktemp -d /private/tmp/gimble-haiku.XXXXXX)" --port 0 --topic "Choose a tea" --interviewer claude-haiku-4-5-20251001
```

Observed directly in the foreground process and its live page:

1. The run started and the page showed it as Running.
2. Haiku turn 1 ended successfully at the harness level after about 6 seconds, but its required structured result was invalid (`unexpected EOF`).
3. Gimble issued its existing bounded structured-output retry.
4. The retry remained active for 75 seconds and never produced the interview question, so the visible answer form never became available. Interrupting the foreground process cleanly ended the run.

This reproduces the same live structured-output divergence that blocked #334 independently of the Svelte form implementation. Focused deterministic checks passed before the probe: `go test ./claude ./web ./internal/workflows/issueseries` and `git diff --check`.

## Scope

No Claude adapter, session runtime, PromiseLoop, or Svelte changes were made from this reproduction. Raw single-turn controls had previously returned valid structured output quickly; this issue tracks the live workflow-path failure and should establish a small causal defect before any correction.
