# Recover workflow role turns from Claude unknown tool_use_id errors

https://github.com/tylergannon/gimbal/issues/371
State: CLOSED

## Observed

A hosted `implement` run stopped while its independent Sonnet QA role was using tools. The coding turn had completed and both task checks recorded exit code 0, but the first `qa-orchestration` turn ended with:

```
claude: result for unknown tool_use_id toolu_01E3c7wQTCkVp1GpK8MtuyYj
```

The CLI reported the entire run failed (`outcome 2`) and no QA verdict was recorded. Run ID: `01M3868V0J5SCHP86Y5A6DN37Y.implement`; turn: `outcome.2/implementation.1/task.1/qa-orchestration.1/turn.1`. The turn lasted about two minutes before the protocol error. This was a Claude tool-result correlation failure, not a deterministic task-check failure or a QA finding. A fresh, separate Sonnet review run was then needed to continue validation.

## Expected

A recoverable provider/session protocol error during a role turn should not immediately discard an otherwise progressing workflow. Gimble should retry or restart that role turn within a bounded policy, preserving prior completed work and recording the original error and recovery attempt. If recovery is exhausted, the run should clearly report the provider failure and where it occurred.

## Reproduction / acceptance

- Simulate a Claude response that references an unknown `tool_use_id` during a workflow role turn.
- Verify that the workflow makes a bounded recovery attempt for that role and can continue to its normal QA verdict when the next attempt succeeds.
- Verify that repeated failure terminates with an explicit provider/session error and does not misreport it as a failed implementation or QA judgment.
- Preserve evidence of each attempt in the run observation.
