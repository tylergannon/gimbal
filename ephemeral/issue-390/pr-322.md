# Fix Claude Generate returning while background work is pending

Claude can emit a successful native result while waiting for background work. Gimble previously returned that intermediate answer, closed its process, and could accept an orphan result as the next call's answer. The adapter now keeps the stream open through explicit waiting and automatic continuations, returning only the final caller value. The next call resumes the same conversation in a fresh process with its own schema.

The private completion format preserves caller schema validation, including Text, recursive references, named anchors, and literal schema data. Pre-prompt results cannot satisfy the submitted request; malformed completion uses the existing bounded validation retry. No background-task disabling, session daemon, or public API was added.

Observed with Claude Haiku on CLI 2.1.270: the real two-Generate workflow yielded waiting, received the matching native completion notification, read the notified output file, and returned the command-minted receipt only after completion. Its second call used a different PID and incompatible schema while recalling context in the same conversation, without work tools or a repeated context token. Input captures showed one host prompt per process. Independent validation repeated this successfully in run `01M3015W4RZY7Y5ZYSJPEJEWYX.claude-wait-schema`.

The temporary fixture initially banned the Read needed to retrieve stdout from the native notification's output-file path. It was narrowly corrected to allow one read of that exact file after the matching completion notification; polling, pre-notification reads, wrong files/tasks, additional work, and hidden host reprompts still fail. The original premature-return baseline remains a failure.

Validation: `just build`, `just vet`, `just test` (all Go tests and 70 frontend tests), Claude race tests, and independent code/evidence review passed. The branch was integrated with current main and its build/vet/test checks passed again. Raw run output and the temporary fixture are not committed.

Legacy draft-04–07 dependency-name maps remain a small follow-up in #321. This PR also includes the investigation and completed Sprint 002 plan.
