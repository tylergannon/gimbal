Fixes #371

Claude observation gaps no longer abort a progressing role turn. An unmatched `tool_use_id` is recorded as an observation gap, and the projector continues with other tool results. Any other raw-message projection error is reported as a diagnostic when possible; the observer returns success so Claude's terminal result remains authoritative.

If Claude or its SDK actually ends a turn with an `unknown tool_use_id` error, `Generate` retries that role turn once in the same session. Both attempts have separate turn records. Exhaustion reports a provider/session error, without presenting it as an implementation or QA judgment.

## Evidence

- `TestRawProjectorRecordsUnknownToolResultWithoutFailingTurn` shows an unmatched result diagnosed while a matched result and step completion still appear.
- `TestProjectionErrorRecordsGapAndDoesNotStopLaterEvents` shows a malformed observed message diagnosed while later step events continue.
- `TestImplementRecoversQAProtocolFailureAndRecordsEachAttempt` runs the implementation workflow with a simulated Claude protocol failure. One successful task check remains recorded; a second QA attempt reaches the assessment when recovery succeeds. Repeated failure produces two failed QA turn records and an explicit provider/session error, with no QA assessment.
- `just vet`, `just test`, and an isolated `just build` passed. The rare live Claude fault was simulated for deterministic verification.
