# Investigate Kit remote-form state_unsafe_mutation during focused composer HMR

## Cross-repository development tracking

Tracked by [SKGO Dev server #349](https://github.com/tylergannon/skgo/issues/349) and its [milestone](https://github.com/tylergannon/skgo/milestone/3). Repository placement records the consumer observation; causal ownership must follow the evidence below.

Observed in the existing Gimbal upgrade worktree on 2026-10-16 using released SKGO v0.35.0, adapter0.34.5, Kit3.0.0 with the existing queue/query patch, Svelte5.57.2, and VitePlus1.0.0.

Open a project conversation composer, type an unsent message, keep the textarea focused, then edit the NewSession.svelte heading. The heading updated and the exact draft survived, but Vite reported an unhandled `state_unsafe_mutation`:

```
HTMLFormElement.handle_focusout
  @sveltejs/kit/src/runtime/client/remote-functions/form.svelte.js:576
  touched[field.name] = true
remove_effect_dom -> destroy_effect -> svelte/src/internal/client/dev/hmr.js:39
```

Ordinary focusout on a settled page was independently exercised without errors; project navigation and composer setup worked after reload. A post-exception model submission was not attempted, so this report does not establish that submissions are unaffected. No AI run was started.

Investigate the focused remote-form HMR teardown path and establish whether it leaves touched/validation state inconsistent. The stack suggests Kit's focusout mutation during Svelte HMR DOM removal; the root cause has not been isolated. This differs from #536's SSR hydration mismatch during simultaneous Go/component edits. The Kit/Svelte versions and patch were already present before the generator adoption.
