## Goal

Move native execution ownership into small, independently running Go executors. Caller loss stops observation, not execution. This is the first step toward restartable workflows; workflow replay is out of scope.

## Two seams and their ownership

| Seam | Executor owns | Gimbal owns |
|---|---|---|
| **Command supervisor** (`gimbal-command`) | One identified command, its process group, deadline/cancellation, stdout/stderr files, and terminal result. | Supplies command identity, arguments, environment and workdir; observes files and requests cancellation. |
| **Agent executor** (`gimbal agent-executor`) | Native session and identified turns for Pi, Claude or Codex; retained JSONL events, terminal results, continuation state, steering and interruption where supported. | Supplies session/turn identities and inputs; consumes events/results. `Generate` retains answer/schema correction; the workflow judges quality. |

These are distinct contracts, not one common wrapper interface. Share small implementation helpers where useful. The agent subcommand ships in the normal Gimbal binary and dispatches before host/web startup. Keep `gimbal run-prompt` simple: run a prompt and show its output, using the executor underneath. No `--detach` mode is needed.

## Local protocol

After acceptance and setup, the CLI emits **exactly one JSON object plus a newline on stdout**, then continues owning the work independently. Diagnostics go to stderr.

Agent:
```json
{"state":"running","socket":"/…/control.sock","events":"/…/events.jsonl","result":"/…/result.json"}
```

Command:
```json
{"state":"running","socket":"/…/control.sock","stdout":"/…/stdout","stderr":"/…/stderr","result":"/…/result.json"}
```

Completed lookup returns `state: "completed"` and retained file locations; the socket may be null. Completion includes failure, cancellation and timeout, distinguished in the result.

Files are authoritative. A lightweight Unix-domain socket provides change notifications and explicit control; no HTTP/SSE stack is required. Agent events have increasing sequence numbers and one complete JSON object per line. Readers resume from their last applied sequence, tolerate replay, and handle partial trailing lines. Subscription/read/wait ordering must prevent missed wakeups. Socket closure is not completion.

Paths are absolute and local to the executor host. The task-host bridge uses existing execution/messaging and artifact routes for remote callers; no shared-filesystem assumption or parallel local-only backend.

## Lifecycle

- The **wrapper owns acceptance and deduplication**, claiming the stable operation ID before native work starts. Concurrent matching submissions find the same operation; conflicting inputs fail. Snapshot file-supplied inputs at acceptance.
- Use named Go string IDs with validated prefixes/ULIDs: command, session and turn IDs at these seams; workflow RunID stays with Gimbal. Gimbal records IDs before submission. State directory, socket location and timeout have defaults; reconnection never resets the accepted deadline.
- Persist terminal results before announcing completion. Completed results/events remain readable after executor exit. Preserve native session identity/history for later turns without requiring an idle executor process.
- Retain the small text files; use **periodic vacuum**, not explicit receipt/acknowledgment. Document retention and deduplication lifetime. Never vacuum active operations or session state still needed for continuation.
- An accepted operation with neither its live owner nor a saved result is an **invariant violation: panic with diagnostics**. Connection loss alone does not establish this. No ordinary uncertain-outcome branch or automatic resubmission.
- Preserve adapter behavior, authentication and configuration, including the existing Go Pi loop and shared Codex app-server ownership. Command supervision covers the owned process group; it does not promise containment of deliberately daemonizing descendants.

## Proof

Run the packaged command supervisor and a real turn for each harness. Demonstrate caller-loss survival, concurrent duplicate submission without duplicate execution, event catch-up, completed-file retrieval after executor exit, session continuation, deadlines/cancellation, bounded-memory large output, and an existing remote route without shared paths. Report observations in the PR, including executor memory separately from native children/shared services.

Also verify:

- Each executor emits exactly one descriptor line; `run-prompt` still displays prompt output normally.
- Events produced during disconnect/reconnect are recovered, and completion cannot be missed.
- Vacuum follows the documented retention policy and preserves active operations and session state needed for continuation.

Cover conflicting-payload rejection and the missing-owner/result panic invariant with focused package tests.

Workflow replay and ID recovery during workflow re-execution, owner failover, a general recovery framework, and Rust/Zig rewrites remain outside this issue.
