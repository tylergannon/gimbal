Compose resource orchestration explicitly in runtime and messaging construction

https://github.com/tylergannon/gimbal/issues/466

## Goal

Prerequisite foundation repairs: #462, #463, #464, #465. This issue prepares construction for the consumer-relative service slice; it does not broaden those repairs.

Make resource orchestration an explicit runtime dependency that messaging implementations can use. Here orchestration means arranging machines/resources and consumer access; ordinary Go continues to own workflow progression.

PR #461 intentionally used hard-wired local destinations and excluded orchestration. At its merge, [messaging factories](https://github.com/tylergannon/gimbal/blob/5d0466cd744173011f8f266417068af0cce55e48/messaging_registration.go) receive JSON configuration, and [runner startup](https://github.com/tylergannon/gimbal/blob/5d0466cd744173011f8f266417068af0cce55e48/internal/runner/runner.go) and [exited-run cleanup](https://github.com/tylergannon/gimbal/blob/5d0466cd744173011f8f266417068af0cce55e48/internal/runner/task_cleanup.go) reconstruct connections. They do not yet declare the proposed resource dependency's construction and lifetime.

## Desired state

Concrete resource implementations are constructed outside workflow code and supplied through the agreed interface. Every relevant process that constructs messaging connections can obtain its properly constructed dependency, including the existing cleanup path. Interface pointers are local to their process; configuration can describe construction but does not transport a live Go object.

Construction, sharing, and release ownership are explicit. Workflow/runtime consumers do not recover concrete implementations by type assertion or discover hidden dependencies through ad hoc conventions. Destinations, credentials, and resource mechanisms remain below the interfaces. Startup does not depend on messaging resources that the same startup has not established yet.

## Proof

- Exercise runtime-loaded messaging and ordinary workflow execution with an externally constructed resource implementation supplied through the interface.
- Demonstrate construction in the separate runner and correct dependency ownership through normal scope cleanup and the existing exited-run cleanup connection path.
- The consumer-relative service slice can use this construction path without workflow source changes or concrete-type access.

Finalize the smallest useful signatures with that service consumer. Do not build a dependency-injection framework, service locator, secret-claim language, scheduler, or workflow crash-resume system. Existing deployments that do not need orchestration should not require artificial resources.
