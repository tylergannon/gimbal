# Issue 227 build brief: extract the workflow graph from Go source

Read `gh issue view 227` first. Its **Shape** section is the Go for the
`workflow` package, verbatim, and its **Extraction** section is the rule. This
brief settles what the issue left open. Where this brief and the issue differ,
this brief wins. Build nothing that is not written here or in the issue.

## Layout

- `workflow/` (import path `github.com/tylergannon/gimbal/workflow`): the
  types from the issue's Shape block, verbatim, plus `doc.go`. polytype
  declaration file `schema.go` under `//go:build jsonschema` following the
  root package's `schema.go`: `var _ = polytype.Declare[Graph]()` (no Schema
  entrypoint: the type is recursive and recursive JSON Schema is unsupported)
  and `polytype.SealedUnion[Operation]("kind", polytype.Snake)`. Directive:
  `//go:generate go tool polytype --typescript ../web/src/lib/workflow`. Commit
  the generated Go codecs and the TypeScript. No `--validate`.
- `internal/graph/`: the extractor. `Extract(dir, entry, name string)
  (workflow.Graph, error)` loads the package in `dir` with
  `golang.org/x/tools/go/packages` and walks the function `entry`. `Source`
  (dir, entry, name, output file) writes the generated Go file. The Go file
  holds one exported var, `Graph`, a `workflow.Graph` composite literal,
  formatted with `go/format`. Header: `// Code generated by gimbal graph. DO
  NOT EDIT.` Strings are `strconv.Quote`d. Load the package with an overlay
  that replaces the output file with `package <name>\n`, so a graph literal
  that no longer compiles against changed workflow types does not stop the
  next generation.
- `cmd/main.go`: a `graph` subcommand beside `lint`: `gimbal graph -entry
  Sprint -name sprint [-o workflow_graph_gen.go]`, run from the package
  directory (go generate's cwd). Default output file `workflow_graph_gen.go`.
- `internal/workflows/sprint/sprints.go`: add
  `//go:generate go run github.com/tylergannon/gimbal/cmd graph -entry Sprint -name sprint`
  beside the polytype directive. Commit the generated file.
- Root package: `func WithGraph(ctx context.Context, graph workflow.Graph)
  context.Context` beside `Project`, a ctx carrier. In `Run`, right after the
  run directory is created: if the ctx holds a graph, its `Name` must equal
  the run's name (else return an error, no run), and the graph is written as
  `graph.json` in the run directory with `json.Marshal` (the generated
  polytype codecs), before `run.jsonl` is opened. A write failure is an
  error from Run. No other new exported name in the root package.
- `cmd/sprint/main.go`: `ctx = gimbal.WithGraph(ctx, sprint.Graph)` before
  `runtime.Run`. The observation store is untouched: `graph.json` sits beside
  the seven tables and is not a table.
- polytype: bump `github.com/tylergannon/polytype` and its `tool` line from
  v1.0.0 to v1.0.3 (`go get github.com/tylergannon/polytype@v1.0.3` and
  `go get -tool github.com/tylergannon/polytype/polytype@v1.0.3`), `go mod
  tidy`, `go generate ./...`, and commit whatever regenerates. A second `go
  generate ./...` must produce no diff.

## Extraction rules

The walk is over one function's statements, in order. A *body* is the entry
function's block, a Scope or Go callback's block, a Tasks range's block, a
Repeat's block, or a Branch's block.

**Operations found in expressions.** Each statement's expressions are
inspected in evaluation order (an if/for/switch `Init` before the statement's
own node), not descending into a `FuncLit` except a Scope/Go callback. A call
resolves as a gimbal call the way `internal/gimballint`'s `gimbalCall` does
(callee package path `github.com/tylergannon/gimbal`); copy the small helpers
you need rather than exporting gimballint's.

| Call | Node | Rule |
|---|---|---|
| `gimbal.NewSession(ctx, role, wd)` | `Session{Name: role}` | role must be a constant string. If the call is the RHS of `:=`/`=`/`var` to an identifier, bind that identifier to `{name: role, role: role}`. |
| `s.Fork(ctx, name)` | `Session{Name: name, From: s.name}` | `s` must be a bound identifier; name constant. Bind the first LHS identifier to `{name, role: s.role}`. |
| `s.Generate[T](ctx, prompt, opts...)` | `AgentCall{Session: s.name, Role: s.role, Prompt, Supervisors}` | `s` bound; prompt constant. Each option: `gimbal.WithSupervisor(sess, instruction, opts...)` → `Supervisor{Session: sess.name, Role: sess.role, Instruction, Supervisors: nested WithSupervisor}`; any other gimbal option (`WithInterval`) is ignored; anything else is a diagnostic. |
| `gimbal.RunCommand(ctx, name, ...)` | `Command{Name}` | name constant. |
| `gimbal.Set` / `SetJSON(ctx, key, v)` | `Set{Key}` | key constant. |
| `gimbal.Scope(ctx, name, f)` | `Scope{Name, Body}` | name constant; `f` a func literal (walk its block as a body) or a package-local function (inline its block). |
| `gimbal.Group(ctx, name)` | `Group{Name}` | bound to the LHS identifier. `g.Go(name, f)` appends a `GroupChild{Name, Body}` to that Group wherever it sits; `g.Wait()` is nothing. |
| `gimbal.Loop(ctx, name, goal, planner)` | `Loop{Name, Planner: planner.name}` at the Loop call | planner a bound identifier. The `for ctx, task := range l.Tasks` over that identifier supplies `Body`; a Tasks range over anything else is a diagnostic. |
| `gimbal.Run(...)` | nothing | diagnostic: Run belongs to main. |

A node's `Source` is the call's position (for a statement node, the
statement's position); `File` is the path relative to the module root with
forward slashes. `Line` is the line.

**Sessions.** A binding is a Go object (`types.Object`) → `{name, role}`.
Reassignment from a bound identifier or a session call rebinds; from anything
else unbinds and is a diagnostic. A session that is not a bound identifier
where one is needed (Generate/Fork receiver, Loop planner, WithSupervisor
session, helper argument) is a diagnostic at that site and the node is
omitted.

**Helpers.** A static call to a function or method declared in the same
package with a body is inlined: its block is walked at the call site as part
of the current body. Parameters of type `*gimbal.Session` bind to the
identifiers passed (a non-identifier or unbound argument is a diagnostic at
the call; the parameter stays unbound). A helper on the inlining stack
already (recursion) is a diagnostic. Helpers without operations contribute
nothing; that is fine.

**Repeat.** A `for` or non-Tasks `range` whose walked body holds at least one
operation is `Repeat{Cond: header as written, Body}`; the header is the
`Init; Cond; Post` or `key, value := range X` text printed with `go/printer`
from the source, with no `for` keyword and no braces. A loop with no
operations in its body is not recorded.

**Condition.** An if/else chain is one `Condition`; a `switch` is one
`Condition` (a case list as written; a tagged switch's case reads `tag ==
list`; `default`/`else` is an empty Case). A branch's Case for an `if` with an
Init reads `init; cond` as written. A branch **exits** when its block's last
statement is `return`, `break`, or `continue` (update the Branch doc comment
to say continue too). A Condition is recorded when some branch holds an
operation or exits, with these exceptions:

1. *Error handling is not shape.* A Condition none of whose branches hold an
   operation is dropped when every non-empty Case is an error test: `==`/`!=`
   against `nil` of an expression whose type is `error`, joined by `&&`/`||`.
   (`if err != nil { return err }`, `if ctx.Err() != nil { return ctx.Err() }`.)
2. *A guard in a helper is not shape.* Inside an inlined helper, an exiting
   branch that holds no operation and comes before the helper has emitted any
   operation is dropped (`command`'s and `git`'s `if in.DryRun { return }`).
   The issue accepts that those commands read as unconditional.
3. *A late return in a helper.* Inside an inlined helper, after the helper
   has emitted an operation, an exiting branch reads `Exits: true` when the
   helper call is in *tail position*: no statement holding an operation
   follows the call statement in its block, and that block is the body itself
   or a branch block that is in tail position of its own block. (`runTask`'s
   `if !passed { return nil }` ends the task body.) When the call is not in
   tail position the branch is still recorded with `Exits: true` and a
   diagnostic says the return ends only the helper. Tail position resets to
   true at every body (callback, Tasks range, Repeat) since a return there
   ends that body's iteration.

Whether a statement holds an operation (for tail position and for Repeat)
is a memoized predicate: the statement, or a same-package function it calls
statically, contains a gimbal operation call. Copy the idea of gimballint's
`workflow`/`reachable` marking; do not import gimballint.

Type switches, `select`, `go`, `defer`, and a `FuncLit` that is not a
Scope/Go callback are not walked; each is a diagnostic when it holds an
operation and nothing otherwise. A call through a function value whose
signature takes a `context.Context` is a diagnostic. A static call into
another package of this module whose package imports gimbal is a diagnostic
(not followed). Nothing else is attempted.

## Tests

`internal/graph` tests beside the code: `Extract` on
`internal/workflows/sprint` asserting the readable facts the issue lists (the
coder's role is `researcher`, its call has one supervisor with role
`supervisor`, the round Repeat holds a Scope `round` holding Loop `sprint`
with planner `planner`, the `!passed` branch exits inside the Loop body, the
`git` commands are unconditional, no diagnostics), and a fixture package under
`internal/graph/testdata/` (Go ignores `testdata` in `./...`; load it by
directory) covering Group/Go, a supervisor of a supervisor, a non-constant
role, a session through a function value, and a helper in non-tail position
with a late return, each asserting the node or the diagnostic. A test that
`Source` output is `gofmt`-clean and compiles is the sprint's generated file
itself compiling.

`gimbal lint ./...` must pass. Tests never go under `ephemeral/`.

## Not in scope

No viewer work, no observation table, no schema for Graph, no `--validate`,
no flags beyond `-entry`, `-name`, `-o`, no expression printing beyond the
Case/Cond headers, no identifiers on nodes, no handling of constructs the
rules above call diagnostics. If a rule here is impossible as written, stop
and say so in the report instead of inventing a rule.
