# Native Go coding harness research

Tyler wants to own an embeddable Go coding harness inside Gimbal, eliminating a Node/Bun process per agent. Reusing or copying a sound Go implementation is welcome, but correctness matters more than stars, marketing, convenience, or avoiding difficult work. A substantial semantic port is affordable. This stage is research and a proposed implementation plan, not authorization to implement or replace the active Pi adapter.

Each report's INDEX.md must state scope, pinned sources, routes, and unresolved coverage. Add a small set of realistic retrieval questions with routes to checked source citations, including an honest account of misses. Do not claim an index is good merely because files exist. Favor useful evidence and navigable notes over duplicative reports.

Gimbal wants ordinary Go, simple boundaries, no reflection, and no generic orchestration framework layered inside its existing workflow system. Shell tools will still launch commands; removing the agent runtime subprocess does not eliminate tool subprocesses. Do not claim measured latency, memory, correctness, compatibility, or one-day delivery without evidence.
