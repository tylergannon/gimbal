## What this source establishes

Public Codex contains generic plugin/MCP exposure and execution gates, computer-use policy schemas and transport, and a separate native user-verification facility. It does not contain the inspected desktop peer-authorization implementation or the native macOS computer-use capture service. Consequently it cannot establish the exact native authorization conditions that distinguish an SSH-origin session from a desktop-origin session, or establish that a launchd worker would pass them.

### Plugin installation and session selection

The loader combines configured enablement (defaulting to true) with `plugin_policy.allows_plugin`. A disabled plugin returns without loading its capabilities. An enabled plugin still needs a valid plugin identifier, an active installation, an existing directory, and a valid manifest. MCP servers are loaded from the manifest and the plugin's server policy. These are actual loading conditions, not evidence of OS permission. Sources: [`core-plugins/src/loader.rs:170–186`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core-plugins/src/loader.rs#L170-L186), [`837–910`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core-plugins/src/loader.rs#L837-L910), [`948–958`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core-plugins/src/loader.rs#L948-L958).

Thread configuration has `disabled_plugin_ids`; runtime projection removes those plugins before producing host MCP configuration. Only active loaded plugins contribute servers, and plugin MCP requirements are applied to those servers. Sources: [`app-server-protocol/src/protocol/v2/thread.rs:190–195`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L190-L195), [`core/src/mcp.rs:380–400`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/mcp.rs#L380-L400), [`core/src/config/mod.rs:1823–1859`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/config/mod.rs#L1823-L1859).

The repository recognizes `computer-use@openai-bundled` and `unified-computer-use@openai-bundled` in cleanup-hook routing, respectively to `node_repl.turn_ended` and `cua_repl.turn_ended`. That proves recognition of externally supplied plugin/server identities; it does not supply their implementation or native authorization. Source: [`plugin/src/bundled_hooks.rs:75–98`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/plugin/src/bundled_hooks.rs#L75-L98).

### MCP exposure and invocation

The catalog applies environment authority before resolving server registrations. An unavailable environment denies them; selected-plugin-only authority accepts selected-plugin registrations; restricted authority checks server/plugin requirements. A denial sets server enablement false. Disabled server names and unsupported EMA authorization can also disable a resolved server. Sources: [`codex-mcp/src/catalog.rs:405–470`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/codex-mcp/src/catalog.rs#L405-L470), [`516–548`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/codex-mcp/src/catalog.rs#L516-L548).

The connection manager starts only enabled servers. Tools must satisfy the enabled-tools allowlist, if present, and not appear in disabled-tools. MCP UI visibility metadata hides a tool from the model unless it includes `model`; absent visibility metadata permits visibility. Sources: [`codex-mcp/src/connection_manager.rs:268–319`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/codex-mcp/src/connection_manager.rs#L268-L319), [`codex-mcp/src/tools.rs:63–102`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/codex-mcp/src/tools.rs#L63-L102), [`connection_manager/tool_catalog.rs:44–64`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/codex-mcp/src/connection_manager/tool_catalog.rs#L44-L64).

Core registers ordinary MCP tools and separately filters Apps tools by Apps enablement and connector policy. Search enablement determines deferred versus direct exposure. Agent-plugin schema budgets can hide tools. An attempted call lacking a prepared available tool is rejected, and an available call can still be denied through action approval. Sources: [`core/src/mcp_tool_exposure.rs:78–88`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/mcp_tool_exposure.rs#L78-L88), [`133–195`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/mcp_tool_exposure.rs#L133-L195), [`core/src/mcp_tool_call.rs:169–185`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/mcp_tool_call.rs#L169-L185), [`273–325`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/mcp_tool_call.rs#L273-L325).

These conditions establish whether a plugin tool can be exposed or dispatched. They do not show that the tool's downstream native service accepts the calling process or can capture a window. A tool such as `cua_repl.js` also encompasses multiple operations; exposure alone says nothing about which of those operations will succeed.

### Computer-use policy fields and model/session metadata

`Feature::ComputerUse` is described as a requirements-only gate and defaults to enabled. A repository-wide search for `Feature::ComputerUse` found only its feature-spec registration; no native capture consumer was found. Its name and default are therefore not a demonstrated native permission grant. Source: [`features/src/lib.rs:321–324`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/features/src/lib.rs#L321-L324), [`1679–1685`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/features/src/lib.rs#L1679-L1685).

Requirements include `allow_browser_and_computer_use`, `allow_appshots`, `allow_remote_control`, and a `computer_use` object. The latter includes `allow_locked_computer_use`, `allow_persistent_approval`, default app access, macOS bundle-ID rules, and Windows app rules. The ordinary computer-use configuration contains default/per-app access. The app-server maps these requirements into its API response. Searches found schema/loading/mapping/tests for the Locked Use field, but no native Locked Use implementation. Sources: [`config/src/config_requirements.rs:1057–1063`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/config/src/config_requirements.rs#L1057-L1063), [`config/src/browser_computer_use_requirements.rs:95–120`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/config/src/browser_computer_use_requirements.rs#L95-L120), [`config/src/computer_use.rs:7–34`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/config/src/computer_use.rs#L7-L34), [`app-server/src/request_processors/config_processor.rs:534–540`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server/src/request_processors/config_processor.rs#L534-L540), [`582–602`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server/src/request_processors/config_processor.rs#L582-L602).

MCP calls carry call ID, current turn metadata, plugin ID when attributed, and thread/session IDs; originating UI calls can additionally carry window/item IDs. REPL-backed calls receive model-selected browser/computer confirmation-policy Markdown, excluding basic Guardian session sources. Public code recognizes `node_repl` and `cua_repl` as REPL-backed servers. Sources: [`core/src/mcp_tool_call.rs:1311–1442`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core/src/mcp_tool_call.rs#L1311-L1442), [`protocol/src/mcp.rs:35–51`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/protocol/src/mcp.rs#L35-L51). The model's Guardian computer-use review mode also controls whether review is required, falling back to the legacy `node_repl_auto_review_required` field. Source: [`protocol/src/openai_models/guardian.rs:165–178`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/protocol/src/openai_models/guardian.rs#L165-L178).

These are policy/identity transport and action-review mechanisms. None of those functions authenticates a macOS socket peer by executable ancestry or code signature.

### Remote, SSH, and local-device checks

The public daemon explicitly supports SSH-launched app-server use. Its Unix detached launch calls `setsid()`. Neither the documented SSH purpose nor session detachment establishes native computer-use authorization. Sources: [`app-server-daemon/README.md:1–27`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server-daemon/README.md#L1-L27), [`app-server-daemon/src/backend/pid_start.rs:160–170`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server-daemon/src/backend/pid_start.rs#L160-L170).

Plugin loading has explicit handling for independently updated SSH app-servers and cached remote plugins. This controls which installation wins; it is not a desktop capture check. Source: [`core-plugins/src/loader.rs:249–269`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/core-plugins/src/loader.rs#L249-L269).

A distinct native user-verification facility is locally gated: initialization activates it only with experimental API enabled, supported device, and either `(InProcess, "codex-tui")` or `(Stdio, "Codex Desktop")`. Its service rejects non-status operations from WebSocket or RemoteControl origins and also checks account identity/platform support. This is a real transport/client gate, but the source describes credential enrollment and challenge signing, not window capture or Locked Use. It cannot substitute for the missing peer-authorization implementation. Sources: [`app-server/src/request_processors/initialize_processor.rs:93–128`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server/src/request_processors/initialize_processor.rs#L93-L128), [`app-server/src/user_verification.rs:56–104`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server/src/user_verification.rs#L56-L104), [`178–213`](https://github.com/openai/codex/blob/07757f448f2d3cf475d0f328732c1c277bce8aa1/codex-rs/app-server/src/user_verification.rs#L178-L213).

## What was not found in this public checkout

Recursive source searches, followed by targeted tracing of config, plugin, MCP, app-server, protocol, and daemon code, found no implementation or occurrence of `authorizeSocketPeer`, `browser-use-peer-authorization`, `untrusted-process-ancestry`, `SkyComputerUseClient`, `cgWindowNotFound`, `CUAService`, or `computeruse.sock`. These are bounded negative findings at the pinned revision; they do not establish absence from other repositories, private source, release artifacts, history, or differently named implementations.

In particular, this public checkout does not establish:

- The executable, signature, parent, or grandparent conditions used by the installed desktop's native peer-authorization module.
- Native service authentication, macOS capture/Accessibility permission checks, Locked Use setup, or locked-window capture behavior.
- Which desktop registration, account rollout, or UI state disables setup toggles while a plugin remains installed/enabled.
- Whether a Gimbal process launched by launchd, an SSH session, a terminal, or the desktop will satisfy the installed service's native checks.

The supplied incident observations—SSH-origin app listing succeeded; locked Finder capture failed with `cgWindowNotFound`; a desktop log reportedly said `untrusted-process-ancestry`; desktop-origin capture and Locked Use succeeded—were not independently repeated in this source-only investigation. The public exposure path permits different failures after a tool is listed. It does not identify the cause of that particular failure or prove that altering process launch origin repairs it.
