# Live desktop integration: what worked and what remains

[Assessment](assessment.md) · [Proposal](../../proposal.md)

**An ordinary desktop-launched MCP adapter can accept an external request and create a desktop-owned Codex task while its owning agent is idle. No polling controller agent was involved. Separately, a task created through the same desktop bridge performed real native macOS capture, typing, and clicking.** These are substantial reductions in risk, but the combined unattended backend is not yet proven: native app access entered `waitingOnApproval`, and the fixture did not have a persistent app approval afterward.

The bounded experiment ran on October 9, 2026, local time, using desktop build 20052. No desktop restart, signing changes, network exposure, or global auto-approval was used. Scripts, source copies, screenshots, and raw observations are retained in the external [spike cache](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/manifest.json).

## Provisioning is separate from each run

Two missing prerequisites were observed, rather than guessed from a missing tool. First, the installed CLI's read-only `config/read` returned a disabled project layer with the explicit reason that the disposable directory was not trusted. After adding trust for that exact authored fixture directory, the custom MCP process started. Second, the custom `bind_probe` tool's default review required approval. That attempt was canceled; a fresh task used a documented `approval_mode = "approve"` override for **only that tool**. No pending dialog was approved by an agent. The provisioned task completed binding without a prompt. [Disabled-layer result](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/ordinary-mcp-config-resolution.json); [exact provisioned MCP config](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/ordinary-mcp-provisioned-config.toml); [executor metadata and lifecycle](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/ordinary-mcp-events.jsonl).

Native app access is another layer. The native call spent 263.5 seconds pending before returning; the task was observed in `waitingOnApproval`. The exact consent resolution was not captured, and the user reported not finding the expected prompt. Therefore the successful native actions must not be labeled unattended. A narrow read of the persistent approval store found the fixture's exact bundle ID absent. No fresh native task was started to provoke another approval request. [Approval observation](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/native-approval-observation.json).

Official documentation provides **Always allow** for future native use of a specific app. Installed source stores this by bundle identifier, independently of thread identity. That supports explicit worker provisioning, but it has not been demonstrated live for this fixture. OS Screen Recording/Accessibility, native target-app consent, and MCP tool approval are separate. Setting an overall turn policy to `never` does not grant missing permissions. Sensitive actions and managed policy can impose additional gates. [Official Computer Use documentation](https://learn.chatgpt.com/docs/computer-use); [source-based approval scope](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/codex/approval-scope.md).

## What the backend can reasonably build on

The plugin idea is viable enough to pursue: desktop-launched code can receive work from another process, use real caller metadata, create a desktop task, and read its result. The tested adapter did one initial model-invoked binding operation; subsequent requests needed no active controller turn. That is not proof of automatic binding after desktop restart. Its worker must have an explicitly managed owning session and reconnection/setup behavior.

The session-control bridge remains a **private installed interface**, not a documented third-party lifecycle API. The test used ordinary project MCP configuration, not a packaged marketplace plugin. Its ingress was a local Unix socket, not a remote network connection. The ordinary-MCP-created child did a simple output task; native capture was demonstrated in the earlier script-created child. Those distinct observations must not be presented as one fully integrated, remotely initiated, zero-prompt native run.

The bound adapter stopped when its owning task was archived and its socket refused connections. One additional unbound MCP process remained in the immediate cleanup snapshot, but exited before the subsequent exact-PID check; no manual kill was sent to it. Do not assume archiving synchronously removes every ancillary process. Archive is also semantically stronger than interrupt: it changes task visibility and may shut down descendants. A final provider integration needs a deliberate cancellation contract, not a substitution of pending MCP-call cancellation for task termination. [Cleanup observations](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/cleanup-observation.json); [later owned-process cleanup](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/extra-mcp-process-cleanup.json); [source trace of archive/shutdown](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/admission-report.md).

The next acceptance check is narrowly defined: a properly provisioned native target app, a fresh desktop task created by the ordinary adapter, and capture/input with **no per-run approval**. Provisioning must be a supported user configuration step; silently granting native consent is not a solution. Remote transport and restart recovery follow only after this exact path passes.

## Experiment hygiene

[Final cleanup](/Users/tyler/Documents/Codex/2026-10-09/gimbal-session-control-research/spike/final-cleanup-observation.json) found no remaining owned processes. All disposable tasks were archived; the hidden browser tab was closed; the Cocoa fixture was terminated. The exact fixture trust entry and project MCP config were removed. The global configuration's original SHA-256 was restored. No product code, installed plugin package, global approval policy, native approval store, or desktop service was changed. Probe scripts and raw output are not committed.

The initial desktop creation calls inherited the configured `gpt-6-astra` model because no override was supplied; that did not follow the repository's cheapest-live-model preference. Later control, MCP binding, cleanup, and MCP-created task checks explicitly used `gpt-5.6-luna`. An initial heartbeat command generated by that model exited immediately due to a Python short-circuit bug; it was discarded as invalid proof, then replaced by a simple external fixture with an actual 120-second loop. The initial browser fixture used a prohibited `data:` URL and performed no action; the separate public HTTPS check used an ordinary permitted page. These failures are retained in the cache rather than counted as successful checks.
