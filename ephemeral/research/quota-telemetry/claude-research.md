# Programmatic Remaining-Quota Telemetry in Google Antigravity (agy) and Anthropic Claude Code

## TL;DR
- **Both tools can surface remaining weekly/hourly quota — but neither ships a clean, officially-documented, non-interactive command or telemetry field for it.** Antigravity's data is reachable via an undocumented local gRPC/Connect endpoint (`GetUserStatus` / `RetrieveUserQuotaSummary`); Claude Code's data lives in undocumented `anthropic-ratelimit-unified-5h-*` / `-7d-*` response headers and an undocumented `GET /api/oauth/usage` endpoint.
- **Antigravity is the easier of the two:** its `/usage` (alias `/quota`) slash command shows per-model 5-hour and weekly remaining quota, and community CLIs (`antigravity-usage`, `agy-cli-usage`) read the same data programmatically as JSON from the local language server. The official `agy` binary has **no** `--output-format json` for `/usage`, and headless `agy -p` cannot render slash commands.
- **Claude Code's OpenTelemetry emits only consumption metrics (tokens, cost, sessions, active time) — no metric reports remaining quota/rate-limit budget.** Remaining weekly/5-hour limits are only obtainable via the interactive `/usage` TUI, the undocumented headers/OAuth endpoint, or community tooling; multiple open feature requests confirm there is no supported programmatic path.

## Key Findings

### Google Antigravity (agy)
- **Official interactive command exists:** `/usage` (alias `/quota`) refreshes model config and quota from the backend and opens an interactive TUI. Per the Antigravity docs, the panel shows "Model Quotas: A breakdown of your usage limits and remaining requests/tokens for each supported model (e.g., Gemini 3.5 Flash, Gemini 3.1 Pro)," with "Active Refresh: The CLI automatically triggers a fresh check of your quotas on disk and from the backend service when you open this panel." There is also `/credits` (AI Credits) with a statusline indicator showing remaining credit count.
- **No official non-interactive/JSON path for quota.** Headless mode (`agy -p`, with `--output-format json`/`stream-json`) returns only per-task `usage` token counts (input/output/thinking/cache/total). Documentation and community sources confirm slash commands like `/usage` do not render in `-p` mode.
- **Undocumented local API is the mechanism.** The running `agy` process (and the Antigravity IDE language server) hosts a local HTTPS gRPC/Connect endpoint on `127.0.0.1` at `/exa.language_server_pb.LanguageServerService/GetUserStatus` (and a richer `RetrieveUserQuotaSummary` in Antigravity 2.x) returning `remainingFraction` and `resetTime` per model, plus weekly and 5-hour groupings. Auth uses a CSRF token (`X-Codeium-Csrf-Token`) and a port parsed from the process args (`--extension_server_port`, `--csrf_token`).
- **Community tools that solve it:** `antigravity-usage` (npm), `agy-cli-usage` (npm; `--json`, `--watch`, and a `GET /quota` HTTP endpoint), `antigravity-quota` (Go), `antigravity-statusline`, and `AntigravityQuota`. Google's own repo has an open feature request — `google-antigravity/antigravity-cli` Issue #46 "Usage and Quota" — where a user reports "the /stats command does not work in AGY and so cannot see the usage or the remaining quota available. Is there someway to get this info and going forwards having it shown in the UI" (labeled `comp:billing/quota`).

### Anthropic Claude Code
- **Interactive commands:** `/usage` shows session (5-hour) and weekly usage bars with reset times (toggle d/w); `/status` also shows allocation. These are interactive-only.
- **OpenTelemetry does NOT emit remaining quota.** The documented metrics are consumption/activity only: `claude_code.session.count`, `claude_code.token.usage`, `claude_code.cost.usage`, `claude_code.lines_of_code.count`, `claude_code.code_edit_tool.decision`, `claude_code.active_time.total`, plus events (`user_prompt`, `tool_result`, `api_request`, `api_error`). No OTel metric reports remaining weekly/hourly rate-limit budget.
- **The API returns rate-limit headers, but Claude Code doesn't expose them.** For API-key usage the documented per-minute headers are `anthropic-ratelimit-requests-remaining/-limit/-reset`, `anthropic-ratelimit-tokens-remaining`, `anthropic-ratelimit-input-tokens-remaining`, `anthropic-ratelimit-output-tokens-remaining`. For subscription (OAuth) auth, the API additionally returns **undocumented** unified headers: `anthropic-ratelimit-unified-5h-utilization/-status/-reset` and `anthropic-ratelimit-unified-7d-utilization/-status/-reset` (weekly), plus `anthropic-ratelimit-unified-representative-claim`. Claude Code receives these but does not persist them to hooks, statusline, or logs.
- **SDK / headless has partial data only.** `--output-format json`/`stream-json` and the Agent SDK emit a `rate_limit_event` with `status`, `resetsAt`, `rateLimitType` — but the `utilization` percentage is omitted in normal (`allowed`) operation. Multiple feature requests (#78476, #40793, #50518, #27915, #34074, #55333) ask for a `claude usage --json` command or statusline passthrough; none is shipped.
- **Undocumented OAuth endpoint:** `GET https://api.anthropic.com/api/oauth/usage` returns authoritative `{ "five_hour": { "utilization", "resets_at" }, "seven_day": {...} }` — the same data powering `/usage`. It requires `User-Agent: claude-code/<version>` and `anthropic-beta: oauth-2025-04-20`, is aggressively rate-limited, and Anthropic has recently blocked non-official clients from private Claude Code endpoints.
- **Community tooling:** `ccusage` parses local JSONL transcripts for token/cost history (not the authoritative limit %); statusline-based scripts read the `rate_limits` object when Claude Code populates it; menu-bar tools (CodexBar, Usagebar, SessionWatcher) poll the headers/OAuth endpoint.

## Details

### Weekly/hourly limit background
Anthropic announced weekly rate limits (in addition to the existing 5-hour rolling window) on July 28, 2025, effective August 28, 2025, for Pro ($20/mo) and Max ($100/$200) plans. Per Anthropic spokesperson Amie Rotherham to TechCrunch, the limits "will affect less than 5% of subscribers, based on their current usage patterns," and target users running Claude Code "continuously in the background, 24/7." Anthropic told TechCrunch that "most Pro users can expect 40 to 80 hours of Sonnet 4 through Claude Code within their weekly rate limits," with the $100 Max plan at "140 to 280 hours of Sonnet 4 and 15 to 35 hours of Opus 4" and the $200 Max plan at "240 to 480 hours of Sonnet 4 and 24 to 40 hours of Opus 4," noting "usage may vary based on codebase size." Per Anthropic's ClaudeDevs account (Aug 29, 2026), standard weekly limits rise "permanently by 25% for Pro, Max, Team and seat-based Enterprise" starting September 14, 2026, replacing a +50% promotional boost that runs "through September 13, 2026 at 11:59 PM PT" — which Anthropic acknowledged nets out to roughly a 17% decrease from the boosted capacity most paying users have today.

Antigravity similarly enforces per-model 5-hour and weekly limits tied to Google AI Pro/Ultra plans. Per the Antigravity Plans docs, "Users on Google AI Pro or Ultra plans can utilize purchased AI credits ... for additional overage usage above the baseline provided quota. AI credits are consumed at standard Gemini Enterprise Agent Platform consumption pricing," governed by an "AI Credit Overages" user setting.

### Antigravity mechanism detail
The reliable programmatic route is the local language server. Tools discover the `agy`/`language_server` process, read `--extension_server_port` and `--csrf_token` from its args, probe nearby ports (typically port+1) for the HTTPS endpoint, and POST to `GetUserStatus` (headers: `Content-Type: application/json`, `Connect-Protocol-Version: 1`, `X-Codeium-Csrf-Token`, and `rejectUnauthorized:false` for the self-signed cert). The response's `cascadeModelConfigData.clientModelConfigs[].quotaInfo` carries `remainingFraction` and `resetTime`. In Antigravity 2.x, `RetrieveUserQuotaSummary` exposes both a Gemini group and a Claude/GPT group, each with a weekly limit and a five-hour limit. `agy-cli-usage` also uses the Cloud Code API path (`POST /v1internal:loadCodeAssist`) reading the OAuth token from the OS keyring as an alternative to a PTY-scraping fallback (it drives `agy` in a pseudo-terminal, sends `/usage`, and reconstructs the screen when the token can't be read).

### Claude Code mechanism detail
The unified subscription headers are the authoritative live source but are undocumented. A minimal probe — `POST https://api.anthropic.com/v1/messages` with `authorization: Bearer sk-ant-oat…`, `anthropic-version: 2023-06-01`, `anthropic-beta: oauth-2025-04-20`, and `max_tokens:1` — returns, for example, `anthropic-ratelimit-unified-5h-utilization: 0.018` and `anthropic-ratelimit-unified-7d-utilization: 0.737` (fractions 0–1) with `-reset` as Unix epoch seconds, plus `anthropic-ratelimit-unified-representative-claim: five_hour` indicating which window is currently authoritative. Note `utilization` is "fraction used," not "remaining" — remaining = `1 − utilization`. Per-model weekly (Opus/Sonnet) breakdowns are NOT present in the headers — only the aggregate — so those still require the OAuth usage endpoint or web UI. `count_tokens` calls do not return these headers. The subagent verification against the official rate-limits documentation (platform.claude.com/docs/en/api/rate-limits) confirmed the word "unified" appears nowhere in Anthropic's docs; only the per-minute request/token headers are documented, while the entire `anthropic-ratelimit-unified-*` family is community-discovered (documented in captures on anthropics/claude-code Issues #12829 and #55333 and independently in steipete/CodexBar Issue #1894).

## Recommendations

**For Antigravity (agy):**
1. For a human in the loop, use `/usage` (alias `/quota`) inside the TUI.
2. For programmatic/CI use, adopt a community tool — `agy-cli-usage` (`agy-cli-usage --json`, `--watch`, or its `GET /quota` HTTP endpoint) is purpose-built for headless weekly/5-hour limits; `antigravity-usage` (npm) or the Go `antigravity-quota` are alternatives. All read the local `GetUserStatus`/`RetrieveUserQuotaSummary` endpoint.
3. If you must avoid third-party code, replicate the local-endpoint call yourself (discover port + CSRF token from process args, POST to `GetUserStatus`). Treat the schema as unstable — it is undocumented and Antigravity is in preview.

**For Claude Code:**
1. For a human, run `/usage` (toggle d/w) or `/status`.
2. For programmatic access under a subscription, the pragmatic route is to read the undocumented `anthropic-ratelimit-unified-5h-utilization` / `-7d-utilization` headers from a minimal `/v1/messages` probe, or `GET /api/oauth/usage`. Both are undocumented, rate-limited, require Claude-Code-matching request headers (`User-Agent: claude-code/<version>`, `anthropic-beta: oauth-2025-04-20`), and carry compliance risk given Anthropic's recent blocking of non-official clients — use with caution and expect breakage.
3. For token/cost accounting (not remaining limit), use OTel metrics (`claude_code.token.usage`, `claude_code.cost.usage`) or `ccusage` on local JSONL.
4. If on an API key (not subscription), the documented per-minute `anthropic-ratelimit-*-remaining` headers are the clean, supported path — but they report per-minute RPM/TPM budgets, not the weekly subscription cap.
5. Track the open feature requests (#78476 `claude usage --json`, #50518 SDK utilization, #27915/#34074 statusline passthrough) — if any ships, switch to it as the supported path.

**Thresholds that change the recommendation:** If Anthropic ships `claude usage --json` or adds a `rate_limits` object to statusline/hook JSON, or if Google adds an `agy usage --json` flag or documents the local endpoint, prefer those official paths immediately and drop the undocumented workarounds.

## Caveats
- **Antigravity's quota endpoint is undocumented and preview-stage;** the schema (`GetUserStatus` vs `RetrieveUserQuotaSummary`) varies by version, and a Google AI Developers Forum report notes `/usage` sometimes showing 100% incorrectly (a known bug where the panel disagreed with actual near-zero remaining quota).
- **Claude Code's unified/weekly headers and the `/api/oauth/usage` endpoint are undocumented,** confirmed by the subagent to appear in no official Anthropic documentation (only per-minute token/request headers are documented). They are rate-limited and gated on a matching `User-Agent`/request shape; Anthropic has blocked non-official clients from private endpoints, raising Terms-of-Service risk.
- **OTel provides no remaining-quota signal for either tool** — only consumption. Do not expect a rate-limit-remaining OTel metric.
- **`-7d-opus`/`-7d-sonnet` header variants were not confirmed to exist;** per-model weekly data is only available via the usage endpoint or web UI, not response headers. A `-remaining` unified variant is mentioned in one community issue but is unconfirmed — `-utilization` is the reliably captured field.
- **The subscription "hours" figures are Anthropic estimates** that vary by codebase and have changed over time; treat them as guidance, not guarantees. One community analysis also reports the "weekly" window behaving as a rolling ~72-hour reset rather than a fixed 7-day calendar cycle in some cases — verify reset timing against your own `/usage` output.
