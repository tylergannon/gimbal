## Route Map & Evidence by Question

### 1. Generation Changes in command.go and source.go
- **Supported facts**:
  - `commandTemplate` in `internal/generate/command.go:96-220` generates a single file (`workflow_gen.go`) inside the workflow package containing `Graph`, `Hosted() web.WorkflowEntry`, and `Command(...) *cobra.Command`.
  - The generated file imports `github.com/tylergannon/gimbal/web` ([`sources/internal-generate-command.go.txt:111`](sources/internal-generate-command.go.txt)) and calls `web.Submit` and `web.Follow` ([`sources/internal-generate-command.go.txt:207,214`](sources/internal-generate-command.go.txt)).
- **Inference**:
  - Inside the workflow package, generation must emit only `Graph` and `RegisterGraph(Graph)`; all `web` imports, `Hosted()`, and `Command()` must be removed.
  - Route handler generation must emit typed `skgo:form` functions in `web/src/routes/` importing the concrete workflow and `internal/host`.
  - CLI command generation must emit Cobra subcommands in `cmd/gimbal` calling the typed Go client generated by SKGO rather than `web.Submit`.

### 2. Defining the Static List of the Five Stock Built-ins
- **Supported facts**:
  - The five stock built-ins are `review`, `implement`, `research-document`, `pyramid-summary`, and `validate-product` ([`sources/cmd-gimbal-workflows.go.txt:36-51`](sources/cmd-gimbal-workflows.go.txt); `implementation-plan.md:26-27`).
  - Currently their associations are duplicated across `cmd/gimbal/workflows.go`, individual `//go:generate` directives, and `cmd/gimbal/defaults.json`.
- **Inference**:
  - A single static definition slice (e.g., `internal/builtin/workflows.go`) should define the canonical list of stock built-ins with their names, package paths, entry function names, and parameter struct types.
  - Route generators and CLI generators iterate over this single slice to guarantee identical inclusion without configuration drift.

### 3. Clean Checkout Generation Without Circular Dependencies
- **Supported facts**:
  - `Justfile:6` executes `go generate ./...` which runs generators across all packages.
  - `internal/generate/source.go:38` passes an empty package overlay to `extract()` so that uncompilable generated files do not prevent re-extraction ([`sources/internal-generate-source.go.txt`](sources/internal-generate-source.go.txt)).
  - SKGO scans `web/src/routes/` using `golang.org/x/tools/go/packages` ([`skgo/internal/gen/scan.go:247`](/Users/tyler/.codex/worktrees/d798/skgo/internal/gen/scan.go)).
- **Inference**:
  - By removing web/CLI dependencies from workflow packages, workflow packages compile purely against `gimbal` and `workflow`.
  - Staging generation into four acyclic phases—(1) Workflow graphs, (2) Typed route handlers, (3) SKGO route scanning & client generation, (4) CLI Cobra commands—guarantees clean-slate builds (`git clean -xfd`) without missing symbols or circular dependencies.

### 4. Decoupling the Two Standalone Examples in examples/
- **Supported facts**:
  - `cmd/examples/interview/main.go` and `cmd/examples/implement-interview/main.go` call `interviewworkflow.Command(...)` and `implementinterview.Command(...)` ([`sources/cmd-examples-interview.go.txt`](sources/cmd-examples-interview.go.txt)).
  - Neither workflow is in the stock server registry, causing runtime submission errors ([`assessment.md:114-121`](../../assessment.md)).
- **Inference**:
  - Decouple `interview` and `implementinterview` from the stock built-in generator: generate only `Graph` in their packages.
  - Update `cmd/examples/` main programs to invoke `gimbal.Run(...)` directly as standalone example runners, preserving their role as runnable examples of Gimbal's library API without requiring host admission.

## Contradictions and Unresolved Questions
- **Contradiction with existing codebase**: Currently `workflow_gen.go` places Cobra commands and `web` imports inside every workflow package. This directly contradicts the requirement that workflow packages have zero web/CLI dependencies.
- **Unresolved question**: Whether `gimbalgen` should remain a standalone binary with flags or be superseded by an integrated build generator in `internal/generate` that processes all built-ins in `builtin.Builtins` in one pass. An integrated pass avoids managing multiple `go:generate` directives.
