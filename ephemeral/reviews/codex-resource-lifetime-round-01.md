# Codex resource lifetime review

Target: `1e3a405e` on `codex/codex-resource-lifetime`, compared with `a3ee508b`, against `ephemeral/worklog/codex-resource-lifetime.md`, `ephemeral/plans/codex-resource-lifetime-proof.md`, and repository instructions. Reviewed the full source/test/contract diff and surrounding adapter transport, recovery, session persistence, worker final-result handling, and task-daemon scope cleanup. Later caller repairs are not included in this verdict.

## Findings

1. **Issue: ending an active scope can re-create its local routing while an unrelated session keeps the connection alive.** `codex/codex.go:529-557` marks the session closing, cancels its active turn and unregisters its route. The cancelled `RunTurn` can subsequently enter `stopConfirmed` (`codex/codex.go:413-415`), which unconditionally registers the thread again (`codex/codex.go:612`). No remaining cleanup removes that restored parent route after the turn returns. With another live session, the last-user socket retirement cannot clear it; repeated ended scopes retain their routing queues for the unrelated session's lifetime. This violates the requested per-scope local release and can produce growing local retention under legitimate parallel work. Reproduced using the existing local fake daemon, two sessions, an acknowledged active turn, and a cancelled Close context; after both Close and RunTurn return, the ended session remains in `conn.threads` (two routes for one remaining owned session). Temporary reproduction: `/tmp/gimbal-resource-review-scope-routing_test.go`, overlay `/tmp/gimbal-resource-review-overlay.json`, failure output `/tmp/gimbal-resource-review-scope-routing.log`. The reproduction ran with `GIMBAL_LIVE=0` and `-race`; it starts no real provider or service. Route admission/retirement must share the session-closing boundary, including stop confirmation and recovery paths, while preserving the other session.

2. **Issue: cancellation still hides ordinary remote-release failures at the worker boundary.** The worker now preserves joined Close/Detach failures in `Result.Error` (`internal/agentexecutor/agent.go:370-404`), but `Wait` returns bare `context.DeadlineExceeded`/`context.Canceled` before reading that text (`internal/agentexecutor/agent.go:491-498`). The outer cancellation path also substitutes `ctx.Err()` (`internal/agentexecutor/agent.go:573-584`). A confirmed interrupted turn followed by failed unsubscribe/archive is consequently reported to the caller as plain cancellation, concealing the uncertainty that the new direction requires reporting without retained cleanup ownership. The new `Unresolved` branch covers native stop uncertainty, but not a normal cancellation joined with an ordinary release error. Reproduced a final result with `Cancelled=true` and `Error="context canceled\nunsubscribe rejected"`: `Wait` returned only `context canceled`. Temporary reproduction: `/tmp/gimbal-resource-review-result_error_test.go`, overlay `/tmp/gimbal-resource-review-result-overlay.json`, failure output `/tmp/gimbal-resource-review-result_error.log`. Preserve both cancellation classification and the final error details through Wait and Adapter.RunTurn, without inventing a cleanup retry owner.
