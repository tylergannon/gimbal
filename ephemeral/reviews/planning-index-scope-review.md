# Planning and Semantic Index builtin scope review

Review basis: `ephemeral/research/builtins-completion/request.md`, its copied `df-sprint-plan.md` and `df-semantic-index.md`, the current planning/index code and focused tests. This is a moving shared worktree: workers are fixing index persistence, audit, retrieval routes and evals while this review is written. I did not run paid models.

## Material findings and disposition

1. **[P1, resolved in the live diff] The interview was programmed to stop after one answer.** The prior follow-up prompt forced `Question` empty even though the loop accepted up to four turns; the fake adapter ignored that instruction. The current prompt allows another essential question, passes all accumulated exact answers, rejects repeats and retains the four-question bound. The multi-question test now aligns with what the real model is asked to do. Native behavior remains part of the parent run's proof.

2. **[P1, resolved in the live diff] Draft differences and decisions could be empty.** The prior schema made `Overview` and `Decisions` optional and still wrote `merge-notes.md`. Both are now required strings; planning rejects an empty overview before interviewing and empty decisions before writing the final plan. The overview is shown to the user before questions. A focused omission test would make this failure path explicit, though the implementation no longer claims success on empty fields.

3. **[P2, resolved in the live diff] Automatic index discovery was disconnected from planning.** The prior `orient(in)` helper had no call site, so a project pointer could be written without reaching the planning agent. `plan` now calls it before any model, adds the discovered entrypoint and corpus path to the brief, and writes that full brief with fixed checks into `intent.md`. The parent is refining the parser and pointer precedence; an implicit-pointer integration test should cover the final path. Explicit `-semantic-index` remains available.

4. **[P2, proof pending] Retrieval usefulness needs an independent query walk.** The fixture `ephemeral/attest/planning-index/retrieval-expectations.json` fixes three queries, source targets and answer facts before the index is built. The intermediate generated `evals.jsonl` had only a generic question with no expected citations; an index worker is correcting that. For native proof, start at the installed README, give a retrieval agent one fixture query without its expected answer, record the route/leaf walked and cited source line, then compare its answer and target against the fixture. Include a nearby false-positive source; the 12-file cache provides these. Keep the transcript and exact installed index path. Do not derive expected targets from generated route labels. This is a proof requirement, not another benchmark framework.

## Scope interpretation

The copied skills justify the workflow behaviors: repo and recent-plan orientation, bounded retrieval of cited prior art, shared intent, three independent drafts and cross-critiques, an interview informed by their differences, explicit synthesis decisions, and a local index with stable entrypoint/routes/citations, freshness and incremental maintenance. The Gimble implementation need not copy Diffusion's model resolver, shell preflight, bundled ledger scripts, `SPRINT-NNN` filenames, Pyramid Index, chapter bookkeeping, sync commands or 10–30 query benchmark target. Those are conventions and tools of the source skills. Reading existing project conventions when present satisfies the requested adaptation.

The current planning workflow has actual orientation and six draft/critique artifacts, not just a generic plan prompt. The index currently has scoped per-source readers, staged installation, citations with checked paths and line ranges, and a direct CLI; these are concrete foundations. Index audit, deleted-source handling, output ownership, source-size handling, route semantics and eval generation are active worker fixes and should be judged on the final diff plus native proof rather than on this intermediate snapshot.
