# Process diagnostics: review adjudication

Round-one attribution, service-stop labelling and repeatability findings are
legitimate requirements defects. Separate the first shared-daemon census as
baseline; report only later first-seen children as candidates, retaining explicit
sampling/other-client uncertainty. Treat stop initiation as a neutral observation,
then qualify persistent survivors after observational grace. Exercise the
observer state and failure paths with repeatable package/subprocess tests.

The request for a maximum duration on an operation that remains active is not a
requirement. Live observer state is capped at 128 owners and 1024 identities per
owner; an operation may legitimately run for an unbounded wall-clock duration.
Constant bounded observation of that active owner is not a retained cleanup
lifecycle. Existing result/reap/stop boundaries end ownership observations, and
post-end checks are time-bounded. No execution timeout or arbitrary loss of
diagnostic coverage is added. Capacity drops must be promptly exposed by existing
observers while active; this is distinct from imposing an observation deadline.

First-round test evidence did not establish built-application behavior. That
proof remains required and will be assessed independently before completion.
