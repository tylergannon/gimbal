# Implementation session: identities and directory-backed run store

**About 50 words:** Give every new run an explicit ULID and automatically persist scope, session and action identities behind unchanged workflow definitions. Introduce a portable event/result store with a run-directory backend. Prove fresh-process readback, identity propagation into local/remote executors, and refusal to dispatch after persistence failure. Execution replay follows in another slice.

## Intended result

A real workflow runs as it does today. Its launcher assigns the run ID; the engine records the identity tree, action requests, events, executor bindings and outcomes through one storage contract. Close the process, reopen the directory in another process, and locate every outcome by its original identity. This does not resume the workflow or skip completed actions.

1. Add runstore record types/interface and directory backend with contract tests. Include node-slot idempotence, append identity/conflicts, exclusive creation/writer, sequential committed readback and streamed blob ownership.
2. Thread required RunID/store configuration through Run and existing admission routes. Initialize header/root before body execution. Move scope/session/action allocation behind EnsureNode while keeping display keys and workflow definitions untouched. Inventory all direct Run callers, generators and fixtures and update the launch side. Check runner.go's id[:26] socket prefix and ProjectWorkspace.svelte/projectHome.ts/CancelGuard.svelte/Topbar.svelte short-ID derivations; both accept bare ULIDs without new parsing machinery.
3. Supply persisted execution IDs to local command/agent adapters and existing remote transports; store the resolved intent before dispatch. Route lifecycle/agent events and raw terminal results through the store, then existing observation reducers. Inventory productive envelope producers in internal/conversation/remote.go:159,368 and internal/environments/operations.go:81,292 as well as the adapters before removing old wire handlers. Stop direct competing authoritative writes for new runs, including ResourceReady callbacks and read-triggered termination. Audit Run signature users in generators/analyzer fixtures as well as launch code. Preserve current native capabilities and cancellation behavior, including retained cleanup after Run returns; route late terminal/cleanup facts through the same store handle or exclusive reopened handle.
4. Run the checks below, inspect a real run and source diff, fix failures, and report observed results. Implementation belongs in a Gimbal task worktree; this Gimbal View worktree holds only the design.

## Focused acceptance

- **Invisible to the author:** an existing workflow definition is byte-for-byte unchanged. It uses a command, a session with two turns and a Group. All new RunIDs/NodeIDs/RecordIDs parse as ULIDs. The stored root/parent/session/executing-scope relationships are correct; display keys are still readable. Include a service and interview in focused tests, without claiming recovery for them.
- **Stable identities:** close/flush the original writer, then use exclusive Open in a fresh process, EnsureNode the same slots/specs and receive the original IDs. Race same-slot insertion, reject changed specs and contradictory outcomes. Invert parallel completion timing and show child identity allocation was completed before dispatch. No workflow is rerun to perform this readback.
- **Real seam:** the same engine path works with a test in-memory Store and the directory Store. No filesystem path/SQL handle leaks through the record interface. New-run event/result readback and observation reconstruction agree, including one failed command and one invalid generated answer/correction sequence.
- **Persistence ordering:** inject failure at node append or intent commit and observe zero native submissions. Fail outcome commit after a command really completed: report recording failure and retain the original executor result, without another submission. Fail after a complete frame write/before acknowledgment and reopen to establish exact committed contents. Under the process-death/page-cache-intact model, truncate only an incomplete last frame; corrupt a fully framed record and require an error. Stream a long event sequence and verify bounded buffering and segment count; block a flush and observe live events before releasing it, while terminal success waits for that flush.
- **Ownership and IDs:** two concurrent starts with the same RunID execute at most one body and preserve the winning live registration. Read/list during initialization and after failed initialization: no external-store substitution, ghost run listing or body execution. Test rejection of a backend that does not declare ExecutionIdentity and an actual old-daemon-shaped HTTP/messaging dispatcher: new identified operation names must be rejected with zero native starts, no ConfirmStarted polling, no DeliveryUncertain outcome and no new pending-cleanup obligation attributable to the rejected action; no retry using old operation names. Exercise that fixture through the workflow turn, workflow command and environment helper. The helper must settle its mutation receipt as not admitted before returning its upgrade message, with empty Result/Error, Attempted=false and its acquired binding released (CleanupPending=false); an explicit retry after upgrade can use the original identity without polling a nonexistent task. Also fail binding release: retain only that real cleanup obligation and finish it before explicit retry admission, without caching the rejection as a permanent operation error. In the isolated no-other-owned-work fixture the root cleanup state is released. A separate existing-owned-resource fixture must retain its real cleanup obligation. Capture accepted local, HTTP and messaging requests (including session creation/close on all supported routes, and fork on local/HTTP routes; messaging fork remains rejected) and assert recorded action/session IDs and owner routes match actual executor admissions. Run one actual remote command on a distinct host and retrieve its output without shared paths; assert the workflow store belongs to the workflow host. Reuse the existing executor fixtures for adapter identity plumbing, plus a real inexpensive native turn to check normal integration.
- **Output independence:** after a successful outcome commit, remove the test executor spool and close the writer and use exclusive Open to read complete output from the run store in another process. A concurrent Open in the same process or another process while the owner is alive must return busy; live UI uses the existing projection path. Large output passes through streaming blob ingestion and existing bounded excerpts. Check consumer-local output references still open correctly.
- **Late cleanup:** force an initial close failure, let Run return, and invoke existing cleanup retry. Assert recorded action/operation IDs, immutable earlier outcomes and final handle closure. Repeat from CleanupExited after confirmed runner death; check exclusive writer acquisition, a distinct stored cleanup occurrence and facts in the same store. Drive the real orphan control entry and assert one dispatch, not orphanCall plus CleanupExited double dispatch. On host restart, normal successful local, failed-body-but-cleaned, and finished in-process runs must produce committed root cleanup-state from finish and then confirmed released projections, causing zero Store.Open calls; pending/unknown runs remain eligible. Drive repeated sweeper ticks with the same failure and assert stable fact/sync counts, then a changed outcome and completion. Snapshot/refresh must append no authoritative fact. Confirm a dead local run with an existing acquired runner.lock and no remote route is terminalized once; active/initializing entries are skipped as incomplete/busy and retried later. A ready non-runner entry with no runner.lock after successful exclusive Open returns settled, without claiming runner death. Pause Store.Create between writer-lock file creation and flock: Open/sweeper must see no ready marker and make no lock attempt. Then pause startup between runner.lock file creation and its flock, run a sweeper and a Snapshot, and prove startup proceeds: the sweeper first sees the held store writer and the reader never flocks. Connect/CleanupPending status checks must dispatch nothing on HTTP or messaging. A concurrent live writer must prevent orphan dispatch. After an injected recording failure, existing explicit stop must still reach its known owned target and report the recording failure without claiming durable acceptance. Exercise an injected non-directory Store through in-process Run and its retained cleanup path. Spawned/remote application runs and their cleanup processes resolve the directory store independently from the same project policy; verify matching locations. Reject a context-only override for an application project admitting routed runs. No cross-process memory-store proof is claimed.
- **Observation:** inspect the running run page: scopes, turns, commands and transcript appear normally; a displayed scope/turn can still be canceled by existing controls. As a unit-level readback check, feed saved facts once into a fresh reducer and compare events/usage. No production reconstruction path or projection cursor is part of this slice.

## Bounded scope

No automatic restart/resume, cached-result execution, startup scan, durable group winner/answer/control semantics, SQLite/SQL implementation, version migration, owner relocation, new executor binaries or conversation activation redesign. Directory reopen and rebuilding observations are storage operations, not a claim of restartable workflow execution.

The likely effort is one substantial focused work session, not a guaranteed single agent context window. The two integration risks to resolve early are propagating preassigned IDs through native adapter/transport boundaries and replacing competing event writes without changing observation. If those expose larger work, report that explicitly rather than quietly adding replay or declaring only the package implementation complete.
