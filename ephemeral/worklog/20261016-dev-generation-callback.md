# Development generator integration

- The helper imports source-analysis tooling and the core workflow model, but names observation roots with `DeclareType`; new selection/worker-retention state lives only in `internal/devgenerate` and its dedicated tooling main.
- Source-first schema generation preserves the active `schema.go` declarations and flags by selecting the pinned Polytype command per affected package. Results compare only the producer's known schema/codecs outputs, including partial changes on failure. Independent TypeScript workers retain their own bounded sessions; stock extraction shares an invocation-scoped session.
- Source selection retains previous Go package directories and embedded-file membership, merges current discovered closure membership, and updates membership only after successful generation. Outputs select their owner for repair rather than treating generated files as authored inputs for every downstream producer.
- Registry additions/removals and changed declaration arguments fail visibly until targeted ownership is reconciled. Frozen reference/legacy trees and test fixtures are excluded. No generic directive executor or whole-application generation is used per edit.
- OpenAPI's configuration `output` overrides its `-o` flag. A private copy of its YAML configuration must override the output path itself before invoking the pinned tool; otherwise the tool writes the application output and leaves a temporary result empty. The fixed-output adapter publishes only the private command's successful bytes and suppresses equal writes.
- Independent review found that Stock's outputs lacked the other producers' ancestor-directory matching. Stock ownership now includes every fixed output/obsolete-output path, recognizes ancestor rename/removal events, and republishes cached products before metadata discovery can fail on the missing invocation package. This repair creates only generated output directories/files, preserves cumulative change reporting through later errors, and does not extract unaffected workflows.
- Real development startup exposed a feedback loop that direct no-op callback checks cannot reveal: creating private OpenAPI scratch files inside the watched module invalidated every full request's raw epoch, so startup repeatedly regenerated instead of admitting an application. Keep both the private configuration and private output in an OS temporary directory outside the module; only the final application output belongs inside the watched tree. Do not hide application-owned paths with SKGO-specific ignores.
