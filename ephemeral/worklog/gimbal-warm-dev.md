# Gimbal warm development

- decision: Appgen must not compile observed application packages merely to identify types. Polytype's source declaration uses the same codegen/cache path, while Gimbal's generator retains shared catalog contracts in the lightweight workflow package.
- finding: internal/builtin/workflow_pages.go embeds generated pages but has no callers. Shipped definitions already contain SourcePage JSON; removing the unused embed prevents output changes from rebuilding the next generator process.
- boundary: Stock projections consume workflow bodies, comments, and source positions. SKGO declaration-only reuse cannot be applied indiscriminately to Stock.
- boundary: Existing web/dev/run.mjs launches Vite and the Go app once; it does not rebuild backend edits. Integration will use SKGO's shared supervisor and retained generation Worker, preserving Vite's workflow preview plugin.
- finding: The existing shared supervisor starts a replacement before stopping its predecessor. A real Gimbal Go edit failed because the candidate could not acquire the exclusively owned project. Integration needs compile-while-serving followed by drain/stop then candidate launch; SKGO now exposes StopBeforeStart for this case.
- decision: Keep Stock's existing compiler-metadata cache validation initially; a third private-workspace framework for its roughly 0.1s selection cost is disproportionate before integrated profiling. Count and report this remaining work rather than claiming all producers are omitted.
- friction: A temporary multi-repository GOWORK also selects fixture packages outside that workspace incorrectly. Standalone test modules explicitly set GOWORK=off; local integration uses /tmp/gimbal-warm-dev.work without committed absolute replaces.
- A frozen producer module copy must rebase its own local replacements too. Main-module overrides selected frozen Polytype, but copied SKGO's unused development replacement still named the live worktree; source capture correctly bypassed with `uncaptured local replacement`, leaving no retained plan. Rebasing that copied go.mod restored body plan hits without changing production code.
- `workflow` is the extractor's compiled Graph/Operation/Description contract, not the authored `internal/workflows` source tree. Its field/variant semantics are directly constructed and serialized by `internal/generate`; changing that contract correctly requires a generator restart. Merely relocating aliases would hide, not remove, this semantic dependency.
- A rendered workflow list is insufficient hydration proof. Verify frontend-only HMR and an ordinary client interaction independently; a Vite websocket update arriving does not establish a changed component rendered. Shared-supervisor exclusive handoff also needs a Vite notification assertion, since incidental generated-file reloads can hide missing success notifications.
- A fresh standalone diagnostic page needs the exact environment module imported by Vite's installed client, not just `/@vite/client`. The former bootstrap returned the diagnostic HTML for that import, preventing automatic repair. The real browser sequence now explicitly navigates while Go is broken before repairing it; `/tmp/gimbal-browser-final.log` and the inspected `/tmp/gimbal-final-diagnostic.png` and `/tmp/gimbal-latest-repair.png` preserve that distinction for the integrated review.
- `workflow/graph.go` is compiled extractor IR: `internal/generate/expr.go` constructs its operation variants, and `source.go` and `definition.go` serialize concrete graph/description values. Ordinary authored workflows under `internal/workflows` and route API declarations are source-only inputs; the actual route field edit is covered by the same browser sequence, including literal generated `badge: string` and eight visible values. Narrowing restart inputs to hide an IR change would execute stale generator semantics.
- `web/runtime.go:startWeb` binds the socket before assembling `NewHandler`; TCP readiness therefore precedes usable HTTP service. In `/tmp/gimbal-dependency-dev.log`, fresh control/socket readiness was 02:15:53 while web serving began 02:15:59; warmed replacements narrowed that gap to roughly one or two seconds. Browser-visible completion, not the supervisor's TCP-ready duration, remains the latency measure.
- Stock's registry previously lacked the `!jsonschema` guard already present on every executable workflow adapter. Projection metadata consequently reported undefined registration functions and fell back to expensive loading. Generate complementary runtime/analysis declarations together; the analysis declaration must fail explicitly if executed, never silently omit real runtime registration. The regression compiles and executes both build selections, and reversing the runtime guard fails it.
- Removing an output's last embed reader must also remove its producer and committed copies. Review caught the unused `internal/builtin/pages` JSON after the embed was removed; Stock now keeps only the snapshots already carried in generated definitions and the live frontend catalog. Restoring the old writer through a Go overlay makes the recovery test fail on the unwanted output directory.
- Actual published-pin browser capture now records Vite WebSocket frames alongside document requests. On body change and repair, two `full-reload` frames arrive before a pending document navigation reports `ERR_ABORTED`; the next navigation renders all eight expected literal rows. The harness does not navigate during those waits. Treat this as duplicate reload work to reduce, not a failed final page or a reason to remove positive browser assertions. Raw timing/frames remain in `/tmp/gimbal-published-browser.log`.
- `just dev` was qualified without any replacement against SKGO v0.32.0/adapter 0.32.0 and Polytype v1.9.0. The earlier frozen-copy logs are historical diagnostics; use `/tmp/gimbal-published-{browser,dependency-tag,native-config}.log` and `/tmp/gimbal-published-dev.log` for current runtime claims. The new browser script requires exactly eight literal rows after each body/API/repair change, and its screenshot URLs are in the PR body.
- Startup regeneration must not fingerprint repaired compiled codecs and then retain the old executable semantics. If `workflow/polytype_gen.go` changes, startup leaves the repair in place and requires rerunning `just dev`; the unchanged second startup proceeds. Disabling that guard via a Go overlay fails the literal repair/restart regression.
- Gimbal-owned handler assembly and the gap between TCP readiness and usable HTTP service are tracked in [Gimbal #535](https://github.com/tylergannon/gimbal/issues/535), coordinated with SKGO #311. The published-pin measurements remain Mac observations; newly reported Linux kernel timestamp collisions invalidate the released shared watcher's freshness assumption and require a producer correction before this integration merges.
- The Linux digest hold is resolved by published SKGO v0.32.2 (PR319); adapter content remains v0.32.1. Final consumer qualification uses those registry/proxy versions, no replacements. `/tmp/gimbal-corrected-browser.cjs` deliberately resets the Go body edit's mtime and still requires eight updated rows, literal API projection and fresh diagnostic recovery. Logs `/tmp/gimbal-corrected-{browser,dev}.log` supersede the earlier0.32.0 timing sample; the extra body-build time is visible in the compiler phase, not hidden as generator work.
- Browser `pageerror` does not capture Svelte hydration warnings. Review found a warning during simultaneous Go API/Svelte edits despite correct final rows. The repeat harness `/tmp/gimbal-hydration-browser.cjs` logs console warnings, reproduces the transient warning, and requires a warning-free settled fresh reload with eight literal rows. Cause remains unproven; track [Gimbal #536](https://github.com/tylergannon/gimbal/issues/536), rather than treating a client recovery screenshot as clean SSR/hydration proof.
