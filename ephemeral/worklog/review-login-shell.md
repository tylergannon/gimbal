# Login shell review

decision: Review PR #503 at its merge commit, isolated from existing root-checkout edits. Review is not authorization to implement changes.
doc_bug: Browser login and server-restart evidence do not cover macOS shell authentication. Its main-frame origin restriction cancels the GitHub navigation, its WKWebView data store is nonpersistent, and native recording commands use a separate ephemeral URLSession without an authentication bridge.
decision: The authentication gate already attaches the customer-defined auth.User to Go request context. Application request-event Locals remain empty; expose that same verified object through the app-owned request boundary if direct event.Locals access is required, without serializing the customer object to the page.
decision: A macOS session credential should remain native-owned and scoped to its configured server. Review any Keychain persistence implementation together with native command authentication, callback handoff, logout, expiry, and server switching.

authority: Tyler authorized increasing session expiration to one week and securely storing the Gimbal login in the macOS app. The implementation must make the shell login and native requests usable and preserve login across app relaunch; the existing provider and users interfaces stay authoritative.
decision: Store only the Gimbal bearer and expiry in a per-server macOS Keychain item. The native loopback proxy supplies it to upstream requests and consumes session Set-Cookie headers, so neither browser storage nor native command clients own a separate login. OAuth flow cookies remain transient; the navigation delegate routes the registered GitHub callback through the same proxy.
correction: The first review traced ApplicationWebCoordinator (document viewers) as though it were the main window. The actual RecorderScreen WebCoordinator allowed GitHub navigation but bypassed the proxy on callback. Both coordinators now hand the callback to the proxy, and the recording status bridge only sends to the local app origin.
friction: Updating and immediately opening the login instance raced the server startup -> verify the server is listening before opening the native app; an initial unavailable page was recovered by app relaunch after readiness.
friction: Native compilation succeeded while warning that the navigation methods only nearly matched optional WKNavigationDelegate requirements. WebKit did not call either policy, and the observed callback lacked its flow cookie -> match the SDK's MainActor/Sendable completion signature and treat this warning as a failed native integration check.
